# 持续更新与纠错

每轮围绕一个问题研究：先读当前包及CHANGELOG，核对已有卡；寻找原始文档/数据/论文，必要时查看原始视频/帖子内容。仅标题、摘要或搜索片段不足以声称完整审阅；检索正文与直接正文需分别标记。

来源登记标题、URL、可确认发布日期、取阅日期、审阅状态、机制版本、商业利益与局限。不能访问的来源进入discovery_queue，不能补写成已经验证。最多保留必要短引用，主要写原创摘要，不存全文/私钥/个人账号配置。

新结论先定位：机制事实、实证观察、原创方法或盈利假设。争议卡标disputed；错误标retracted，保留理由与旧ID，不覆盖历史。更新同一ID提高version，新ID只用于不同论断。更新来源后核查所有引用卡。

更新必须解释：新增什么、修正什么、为何、哪些实验受影响。官方机制变化不直接变成盈利规则；经验帖子只提出可证伪候选。收益晋级需要数据集、成本、容量、样本外与不确定性证据。

新增实验写proposed_not_run，result=null。真正运行后记录run_id和报告，不可把计划写成完成。修正候选数量或验收门槛应开新实验版本，完整保留失败试验。

维护CHANGELOG、manifest和SHA256，运行validate_kb.py。以同一持久文件的新版本更新，冲突时重新读取最新版本，不覆盖别人的改动。定期回归eval问题；结构校验通过与模型理解通过是两回事。

建议研究顺序：交易执行与费用 → 历史候选覆盖 → 退出与容量 → 操纵识别 → 叙事可见延迟 → 分布变化。没有可靠新增时报告无升级，不为凑条数降低证据标准。

运行时间由外部定时任务触发，本包不含常驻爬虫。任务未运行时不会持续联网或自动改写本地模型。定时研究也不代替真实数据的模拟验证。
